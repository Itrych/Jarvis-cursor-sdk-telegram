# Участие в разработке

[English](CONTRIBUTING.en.md)

Изменения принимает владелец репозитория. Ниже порядок, в котором устроена работа с кодом.

## Подготовка

Нужен Python 3.10 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -e .
copy .env.example .env
copy config.example.yaml config.yaml
```

`.env` и `config.yaml` заполняются локально и в git не попадают.

## Проверки

Тесты стандартной библиотеки, без отдельного раннера:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Перед коммитом имеет смысл прогнать их, если менялись пути файлов или сборка текста стрима.

## Стиль

- Комментарии в коде на английском.
- Сообщения коммитов на русском. В сообщении важнее причина изменения, чем перечень файлов.
- Один документ — один язык. Русская страница не дополняется английским абзацем, и наоборот. Имена команд, файлов и продуктов остаются как есть.

## Что не коммитить

- `.env`, токены, ключи, базы сессий в `data/`
- `config.yaml` с путями конкретной машины
- `_docs/`, `_other/`, `AGENTS.md`, `.cursor/`
- Виртуальное окружение и кэши сборки

Если секрет уже попал в историю, ключ нужно отозвать и выпустить новый. Удаления файла из последнего коммита недостаточно.

## Изменения

1. Ветка от `main`.
2. Коммит на русском.
3. Запись в [истории изменений](CHANGELOG.md) для поведения, которое увидит пользователь.
4. Pull request владельцу репозитория.

Релиз на GitHub описывается по-русски и указывает на соответствующий раздел истории изменений.
